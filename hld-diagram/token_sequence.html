    Note over C,S: Step 1: Login through Seva Sindhu
    C->>S: Log in (Citizen, or assisted mode as a K1 / B1 / G1 / AJSK / BSK franchise)
    S->>S: Issue the Token and the unique edcsApplicationRefNo
    S-->>C: Auto-submitting POST form for the department

    Note over C,D: Step 2: URL 1, the Department URL (provided by the department)
    C->>D: POST UserId, edcsApplicationRefNo, Token, assistedmode, ServiceId (mobile, digilockerid if required)
    D->>D: Verify the token received from SevaOne
    D-->>C: HTTP 200, access allowed
    C->>D: Fill the application form and pay the department fee

    Note over D,DB: Step 3: URL 2, the acknowledgement receiver (provided by SevaOne)
    D->>D: Generate the final acknowledgement
    D->>A: POST .../api/TokenIntegration/department-update (JSON, Authorization: Basic)
    Note right of D: UserId, DepartmentApplicationRefNo, EdcsApplicationRefNo, Token,
payment status, fee date, fee, payment reference,
acknowledgement file type, date and base64 file
    alt URL 2 call succeeds
        A->>DB: Save the response
        A->>DB: Set status to SUCCESS
        A-->>D: {DepartmentApplicationUpdateId, EdcsApplicationRefNo, DepartmentApplicationRefNo}
        D-->>C: Redirect the browser back to SevaOne
        C->>S: Return to SevaOne
        S->>DB: Read the saved response
        S-->>C: Print the acknowledgement
    else URL 2 call fails
        A-->>D: {"Message": "Data Not Inserted"}
        A->>DB: Show the transaction as Failed
        Note over D,A: The department calls URL 2 again until it succeeds
    end
